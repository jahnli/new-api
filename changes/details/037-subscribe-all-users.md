# 公司订阅、分类额度与高级模型限额

**日期**: 2026-10-14

## 公司范围与额度调整

- 套餐按公司限制可见性，购买和批量更新均校验范围。“全员订阅”仅替换所选启用公司中同套餐当前生效的订阅：状态 active、已开始且未结束；保留当期已用额度，其他用户跳过，不新增订阅。符合条件的禁用、注销用户也处理。
- 管理员按人民币金额调整当前有效订阅的总额度、标准或高级额度；汇率换算及额度转换严格拒绝超限。减少后不得低于已用额度或变成代表无限的零值，无限额度不可减少。
- 分类调整原子更新额度与覆盖比例，检查版本和两位小数舍入。手工金额增减仅当期有效，重置恢复当前套餐总额；用户覆盖比例保留。

## 高级模型限制与记账

- 策略默认关闭，默认比例 100%；全局及后端用户比例支持 0–100、最多两位小数。管理界面手动覆盖限制为 1–100 正整数，继承默认仍接受完整策略精度。
- 高级请求同时占总额度与高级额度，标准模型可用全部剩余总额度。修改策略不清空占用；初次预扣和追加预留检查分类限额，实际结算允许高级分类超额并记录，总额度不足保留待结算。
- 按请求、目标净额和修订号持久化预留、结算及退款；零差额也完成状态迁移，重试不能重复应用。重置清零分类占用并增加周期版本，旧周期请求不改当前周期余额；有记账关联的订阅禁止直接删除。
- 任务保存订阅请求及修订号，任务持久化后再结算；消费与任务日志保留高级分类、比例、周期、计费模型、净占用及超额快照。
- 高级预留不足返回 HTTP 402 和 `subscription_premium_quota_insufficient`，不改变既有订阅／钱包偏好与回退规则；双重不足保留两种原因。独立限频通知在高级预扣不足时触发，即使钱包随后支付成功也可提醒；充值钱包不直接增加高级额度。

## 管理界面

- 订阅管理分“订阅套餐／额度策略”页签，策略为页内表单，保留模型多选、不可用模型回显、版本并发校验及缓存刷新；只读高级模型清单供登录用户查询，不开放管理配置。
- 套餐与用户订阅使用居中弹框；全员更新必须选公司，显示加载、失败与空状态。用户订阅区表格内部滚动，复用身份组件与额度明细。
- 增减入口直接展示，正数金额才可提交；弹框实时预览总额、高级额度及占比变化，按原始值显示方向，窄屏换行，提交中禁止关闭；实际结果以服务端校验为准。
