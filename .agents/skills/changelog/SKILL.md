# 维护变更日志

读取适用 AGENTS.md 及[项目配置](../../skill-project.md)的 `changelog`。明确要求更新时执行，提交前自动维护由当前项目或本次请求决定。创建、检查或修改技能本身不运行日志流程。

## 类型与输入

- 从配置和正文确认路径、模式与格式。`local-customizations` 是当前有效二开清单，`release-history` 是保留版本事实的历史，不能混用。无配置先查现有日志；无法判定则澄清，不擅自转换类型。
- 先看 `git status --short`，分别读取 `git diff --cached --name-status` 与 `git diff --name-status`。暂存区有相关改动则默认分析暂存内容，否则分析工作区和相关未跟踪文件。diff 返回 0 不代表有内容，不能用 `A || B` 判断为空。
- 部分暂存时按选定版本读取，不能把未暂存功能写进仅描述暂存改动的日志。无法隔离时说明范围并保留索引。
- 无用户或业务影响的技能、工具、日志自修改、格式化与注释通常跳过；不能仅凭 `.github/`、锁文件或文件名排除部署、兼容性、安全等实际行为变化。

## 本地定制清单

仅记录相对已集成上游的本地新增或行为变化。纯上游同步、上游能力、合并统计、冲突过程和仅保留原行为的适配不写索引或详情；同步期间额外实现的独立本地功能只记录功能本身。

1. 读取主索引全文，按主题完整读取相关详情，结合选定 diff、入口与必要历史核实语义。
2. 同一业务能力的持续调整合并回原条目，保留编号，写最终行为，更新为实际业务变更日期。共用文件或目录只是线索，不能据此合并权限、计费、界面等不同能力。
3. 本地新增后完全撤销、无遗留差异时，同时消除新增和撤销描述；部分撤销只删对应部分。搬迁、改名、替代写当前实现；本地删除上游能力仍是有效差异。迁移、旧值转换和兼容约束有效时保留。
4. 固定实际已集成的上游 SHA，不用未合入的最新上游作基线。证据不足保留原文并说明，不只凭文件消失或搜索未命中删除。
5. 仅新能力新增条目。沿用编号格式，取当前最大数字编号加一，至少三位补零，不按行数或最后一行推算，不复用空缺。已有重复编号先说明，不顺带重排。

编号表格沿用“编号、日期、说明、详情”和中文说明，日期 `YYYY-MM-DD`。相关文件不超过 3 个时在详情列用反引号路径、顿号分隔；超过时按配置创建详情 `{编号}-{英文短标识}.md` 并用相对链接。其他日志结构保留原样，不强制转成表格。

索引概括“能力、当前行为和必要条件”；详情保留角色、权限、默认值、限制、异常回退、入口与兼容要求，清除过时过程与重复段落。索引、详情、清单及链接同步更新；详情仅在专属内容失效且无其他引用时删除，共享详情只删对应部分。

## 发布历史

按现有版本、分类和语言写入未发布区或指定版本，保留已发布条目与历史撤销事实。是否收录上游变化按项目政策及发布范围判定；不套用二开清单的消除、跨版本合并或“上游永不记录”规则。不猜版本号、发布日期或部署状态。

## 验证与交付

检查实际 diff、`git diff --check`、编号唯一性、表格和相对链接。仅日志变更不启动业务栈。说明新增、合并、消除或跳过的主题及证据限制。

默认只改日志，不提交或推送。只有本次授权或 `changelog.stage_after_update` 明确要求才暂存本次日志变化；已有无关暂存或日志部分暂存时，不用整文件 add 混入其他内容，保留并说明，或按明确授权精确暂存。
