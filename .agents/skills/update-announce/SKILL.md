# 功能更新公告

默认只读分析，不改代码、日志或版本号，不提交、推送、部署或发送通知。创建、检查或修改技能本身不生成公告。

## 项目与范围

- 确认目标仓库，读取适用 AGENTS.md 及[项目配置](../../skill-project.md)的 `project_name`、`announcement` 和日志位置。配置缺失时从当前 README 或清单核实名称，标题为“项目名称 功能更新公告”；不继承技能原仓库的品牌、业务或部署状态。用户指定标题、读者或格式优先。
- 优先使用指定 BASE/TARGET 版本并固定完整 SHA；否则固定当前 HEAD 或指定分支，按日期选主线基线与截止版本。只统计已提交内容，不混入工作区改动。
- 当前日期和时区优先使用会话提供的用户时间上下文，缺失时查询；不以宿主机时区覆盖用户时区，不沿用文档示例日期。默认从当前时刻向前一个日历月至今，月末截断，不等同于 30 天；“上个月”取上个完整自然月。
- 明确起止日期包含两天，内部按起始日零点至结束日次日零点的左闭右开区间；“某日当天”仅该日，“从某日开始”至今。缺少年份取当前年并输出完整日期；结束晚于现在截到取数时刻，倒置或有实质歧义时澄清。
- 记录分支、SHA、取数时间、区间和浅克隆状态。历史不足说明覆盖限制，不当作没有更新。历史时段固定截止状态，不引用其后的功能。

## 调查与核实

1. 用 `git status --short`、`git rev-parse`、`git log`、`git show`、`git diff` 完整调查范围。日期默认看带时区的提交者时间；选基线时核查主线顺序与祖先关系，时间戳乱序或历史不全时不能假定完整覆盖。
2. 主线确认何时合入，同时读取 `BASE..TARGET` 完整可达历史及净差异。合并带入的旧日期提交也可能属于本期；不能只看 `--first-parent`、近期若干条、作者或提交前缀。用合并相对第一父提交的差异核实接入内容，避免重复。
3. 阅读候选差异及 TARGET 中入口、实现、权限和配置条件，日志只作线索。公告可含实际采用的上游能力，不要求补写二开日志；本地已有等价能力不能宣传为本期首次获得。
4. 合并连续调整，检查撤销、替代和最终状态；新增又完全撤销的不列新增。提交标题不能单独证明功能、性能比例、价格、支持范围或上线状态。
5. 保留提交和文件依据供追溯，默认不把 SHA、内部路径和调查过程写进公告。用户明确提供的业务通知可作补充来源，但不能伪称 Git 已实现；需外部核实的事实使用相应可靠来源。

## 内容与分类

用简洁中文说明场景、变化、用途和必要条件。优先用户可感知的能力、修复与兼容性变化；无用户影响的格式化、重构、依赖、CI 或技能维护通常省略。区分用户与管理员权限、支持能力与实际启用。无部署证据不写“已上线”，默认用中性功能措辞，不加无关免责声明；用户询问发布状态时如实说明。

- Featured：用户或项目指定的重点，以及有证据的重要兼容、迁移或停用事项。业务专项重点按 `announcement.featured_topics` 及补充约定判断，不预设所有项目都有模型或价格业务。
- Feat：其余新增或扩展能力、入口、配置、接口及普通交互改善。
- Fixes：已有功能的独立错误或兼容性修复，说明修复前后；本期新能力的连续补齐合并回该功能。
- Perf：实际差异支持的响应、吞吐、内存、网络、查询或并发效率改善。布局和普通重构不算性能，无测量证据不写比例。

先提取 Featured，同一变化只出现一次；同一模块的独立变化可分开。不能只照搬提交前缀。提醒、配置前提和迁移说明并入对应条目，不另设“更新注意事项”。空分类省略，不凑条数。

## 默认交付

完整公告放在单个 `markdown` 代码块，保留可复制源码，不重复给渲染版或分析过程。明确要求富文本或落盘时遵循用户要求，写文件前检查目标和已有内容。

第一行为实际更新范围，空一行后为配置或核实得到的加粗标题。分类为不编号的加粗无序列表，条目缩进两个空格；范围、标题、分类及分类与条目间留空行，同类条目连续排列。仅主标题与分类标题加粗，不加 Markdown 标题前缀、表格或手写圆点。

下例只示范格式，交付时替换日期、项目名与内容，省略空分类：

```markdown
更新范围：YYYY-MM-DD 至 YYYY-MM-DD

**项目名称 功能更新公告**

- **Featured**

  - 重点事项：经核实的变化、影响及条件。

- **Feat**

  - 功能名称：新增能力及用途。

- **Fixes**

  - 功能名称：原先问题及修复后的表现。

- **Perf**

  - 使用场景：有依据的效率改善。
```

没有更新时，标题后直接用列表写“该时间范围内暂无可确认的功能更新”。交付前核对范围、最终代码、归类独占、权限与项目标题。没有发送授权不调用外部通知工具。
