# main 上游合并与部署

创建、检查、修改或解释本技能不执行工作流。执行请求覆盖用户明确要求的阶段；读取配置不构成推送或部署授权，已有明确授权无需重复询问。

## 解析项目契约

1. 确认目标 Git 仓库根目录，读取适用 AGENTS.md 及[项目配置](../../skill-project.md)的 `main_upstream_deploy` 节。项目相对路径以目标仓库根目录解析，不以临时克隆或技能安装位置解析；不读取其他项目配置。
2. 配置了 `workflow` 时，完整读取该项目适配及适用参考，按其操作范围、验证、发布方式和重试上限执行。只拉取镜像与先构建多组件镜像是不同的项目契约，不能相互套用。适配缺失时报告，不回退到猜测的默认流程。
3. 未配置适配时，仅在用户或当前项目资料明确给出 fork、main 分支、上游来源、验证命令、发布方式及部署目标后使用下方通用流程。仅有 SSH 凭据或另一个 release 技能不足以确定目标；集中说明缺项，先完成不依赖缺项的只读调查。
4. 凭据配置按项目契约定位，须同时满足 Git 未跟踪和被忽略。不打印完整配置，不把密码、私钥或令牌写入命令行、日志、技能或 Git。按已确认的项目契约验证主机身份，指纹变化停止。

## 无项目适配时的通用流程

- 固定 fork main、上游分支及共同基线 SHA，在独立临时目录克隆 fork。只在该克隆写 Git，不切换原工作区分支、不暂存用户改动、不修改 Git 身份。
- 比较上游变化与本地定制，读取当前检出版本的领域与验证规则。合并固定上游 SHA，保留提交前审查和验证窗口。遇到冲突，在本次干净隔离克隆中中止合并并报告；不批量选边，不擅改业务规则。
- 通过适用检查后创建必要的合并提交；已包含上游时不造空提交，核实待发布 SHA 与验证证据。检查失败或必要环境受阻时停止后续发布。
- 按明确的目标普通推送，不强推、不顺带同步其他分支。并发前进时至多重新获取、审查、合并和验证一次；仍冲突或失败则停止。提交信息拒绝仅在满足同仓库 `git-push-skip-lint` 条件时回退。
- 需要构建时按项目镜像发布流程触发一次，跟踪同一运行并核实 source SHA 与所有必要产物；结果未知先只读查询，不重复触发。只拉取既有镜像的流程不能声称构建了本次 SHA。
- 只更新明确的实例、目录、服务与镜像，保留卷、数据和其他配置。依次执行项目批准的命令；不自动 down、删卷、prune、回滚或混用其他部署渠道。结果不明先查询，不重复重建。
- 按项目契约验证运行版本与健康；限定命令的适配按其范围执行，不能以通用步骤追加命令。

## 交付

报告最终 SHA、实际验证与推送目标、发布运行及产物、部署目标和命令结果。区分通过、失败、未运行和环境受阻；命令退出成功不等于运行版本、接口健康或业务验收已验证。失败时列出已完成与未执行阶段，保留隔离克隆及证据，不自动清理工作区。
