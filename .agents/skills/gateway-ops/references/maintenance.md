# 脚本接入与更新

此模式用于维护 `gateway-ops` 的能力清单和运行说明。只修改本技能目录中的必要文件，保留用户已有改动；不修改源脚本、配置、数据库、价格参考数据，也不执行运营操作。它在用户调用时工作，不是文件监听器或定时任务。

## 识别变化

1. 在项目根目录用 `rg --files scripts` 获取当前文件，并与 `SKILL.md` 的指令映射和参考文件对照。不要只看 Git diff：需要覆盖未跟踪的新文件，以及尚未记录的历史脚本。Git 状态与差异可辅助定位重命名和代码变化。
2. 全量更新时核对所有已接入入口的当前参数解析、配置来源、主流程、输出和副作用；不能只核对文件名。指定单个脚本时只接入该脚本及必要的共享说明，不顺带重写无关能力。
3. 区分新增候选、已接入且说明过时、已删除/重命名、无需变化。脚本目录可能包含子目录和 Python 以外的语言，按实际解释器与入口处理；不要把生成文件、图片、JSON 数据、库模块、测试或缓存当成运营入口。
4. 分类依据是源码中的可调用入口和实际用途，不只看扩展名、文件名、注释或 `__main__`。检查入口调用及会影响行为的本地依赖；工具模块可被其他入口复用，不因此新增独立指令。当前 `scripts/official_model_prices.json` 是参考数据，保持不接入执行。

只读差异检查到此及必要源码核对为止，返回候选与变化说明，不修改技能。明确要求更新时继续下面步骤，无需逐文件重复确认。

## 接入或修订能力

逐个读取候选源码并记录实际支持的内容，复用现有表格和领域参考文件，不为每个脚本机械新增文档：

| 要核实的内容 | 写入技能的规则 |
| --- | --- |
| 用途与入口 | 用户能用什么中文需求调用；实际脚本相对路径、解释器及最低版本 |
| 参数 | 必填位置参数、可选开关、类型/范围、默认值及参数之间的约束；命令示例须与源码一致 |
| 运行条件 | 依赖安装名与导入名、工作目录、输入文件、环境变量和配置加载优先级 |
| 对象与时间 | 默认站点/分组、对象匹配方式、时区和区间边界；不照搬其他脚本的假设 |
| 副作用 | 本地文件创建/覆盖、数据库/API 写入、对外发送、删除、费用或其他不可逆动作 |
| 执行控制 | 有无真实的预览开关、何时写入、备份与覆盖范围、失败/超时后如何核对状态 |
| 结果 | 成功与失败信号、退出码、真实输出位置、能交付的摘要和文件 |

- 不通过 `--help`、导入模块、`runpy`、调用主函数或预览模式探测行为；这些路径也可能连接数据库或产生副作用。使用源码阅读或 AST 等不执行源码的静态分析。动态参数无法静态确定时明确列出缺项，不编造命令。
- 新入口与现有中文意图重叠时，按业务结果区分，如“导出新表”和“更新现有表”；保留已有可用指令。不把含糊指令默认映射到副作用更大的操作。
- 不假设所有新脚本都支持 `--apply`、`--output` 或 `.env`，也不把没有预览机制的命令伪装成预览。没有预览时据实说明，根据实际副作用和用户请求确定执行条件。
- 在核查计费用量、价格或其他受项目强制规则覆盖的脚本前，先完整读取适用规则；任务插件或认证脚本还需遵守相应阅读要求。维护过程不改业务逻辑。
- 读取到秘密配置时只记录变量名、来源和非秘密限制，不复制 DSN、密码、令牌、Webhook 或个人数据到技能。
- 超出网关运营范围的部署、仓库维护、开发构建等脚本，记录为未接入并说明原因，优先沿用已有专用技能；不为了覆盖全部文件而扩大 `gateway-ops` 的职责。
- 行为暂不明确的候选保留为未接入项，说明缺少的具体信息；继续处理能明确核实的其他项。不用模糊的“已支持”掩盖缺项。

## 更新位置与失效入口

- 在 `SKILL.md` 指令映射表维护实际入口和领域参考链接；用 `references/reports.md`、`references/prices.md` 保存对应领域的细节。只有出现独立且足够复杂的新运营领域时才增加参考文件，并从入口链接。
- 新增能力确实超出入口描述覆盖范围时，兼容更新 frontmatter 的 `description`。UI 简介需要改变时按可用的 `skill-creator` 元数据规范修改 `agents/openai.yaml`，保留无关字段和默认发现策略。
- 脚本删除后移除可执行映射和过时示例；重命名后更新所有相关路径和命令。只有核实替代脚本具有对应语义时才保留旧中文指令到新入口的映射，不能静默替换为功能不同的脚本。
- 本次未能接入的真实候选及其具体原因可简短记录在最相关参考文件中，便于下次复核；不用额外维护一套重复清单、自动生成 README 或创建仓库 `docs/` 文件。

## 静态验证与交付

- 采用可用 `skill-creator` 的 `quick_validate.py` 校验技能格式；从其实际安装位置定位工具，不把本机绝对路径固化到本技能。
- 核对 Markdown 参考链接、脚本路径、命令参数和位置参数顺序。解析脚本时不执行它；业务运行条件和真实运行效果不能由静态校验替代。
- 检查修改内容的空白格式及 Git 差异，确认只维护技能文件；仓库禁止运行测试时不新增、不修改、不运行测试，也不为更新技能运行运营脚本或安装业务依赖。
- 返回新增、变更、移除、未接入的摘要，给出新增能力的可复制中文调用示例，说明实际静态验证命令与结果。没有实跑时明确说明；如果无差异，直接报告无需更新，不做无意义改写。
